# stuck

形成一个很小的“假设 → 实验 → 观察”循环，不是 debugger。[English](README.md)

```sh
stuck [--hypothesis <text>] [--] <command> [args...]
stuck cargo test
stuck --hypothesis "增加 etcd dial timeout" cargo test
```

连续三次完全相同的失败后，第四次相同调用在前台控制终端询问“这次你打算改变什么？”。
EOF、空白或无效回答返回 125，不启动子命令，也不清除已有次数。
有效显式参数/交互回答只放行本次并开始新链（首次失败计 1）；任何一次调用均可提供，
不会永久绕过，也不自动复用历史假设。没有质量评判、NLP、AI、debugger、自动重试或命令改写。

假设去除首尾空白后必须非空单行，最多 512 个 Unicode 字符，显式无效值返回 2。
工具选项放在子命令之前，argv 原样保留；shell 功能需显式写 `sh -c`。
帮助、版本、`--verison` 和中英文提示沿用公共契约。

## 精确失败签名

签名包含 cwd/argv 摘要、稳定 Git 代码快照、正常非零退出码，以及分别计算的
stdout/stderr 原始字节摘要和长度。不归一化时间戳、颜色或路径。
命令/代码/输出/退出码变化、成功、并发歧义均重置旧链；信号、启动失败、
输出读取或转发不完整不算可靠失败样本。旧链超过 30 天失效。

两条管道并发消费、实时转发到各自原始流，以固定缓冲区增量计算带密钥 BLAKE3。
不积攒或保存完整输出，每流保序，不保证跨流交错顺序。
子命令看到的是管道：**不是透明 PTY**，不适合全屏交互程序。
stdin 始终继承，只有确认 stdin/stderr 是前台终端才从 `/dev/tty` 提问，不挪用管道输入。

非 Git、无 Git、冲突/子模块/过滤器、快照/状态/锁故障或输入不可比较时放行真实命令。
尤其是管道/重定向 stdin，即使有旧失败链也不会拦截。只有可靠且可比较的调用到达门槛，
但回答不可用时才返回工具自身的 125。记录失败不改变子命令结果，不虚称假设已保存。

使用真实 argv、共享前台进程组、无自制信号处理器。真实退出码透传，信号为 128+N，
程序不存在 127、不可执行 126。真实子命令也可能返回 125，内部结果类别会区分。
不创建 detached 子进程，但不约束命令故意 daemonize 的行为。

## 隐私与状态

**假设是本地明文，不要填写密码或令牌。** `--hypothesis` 还可能进入 shell 历史和进程列表。
只记录程序 basename 和本地带密钥 argv 摘要，不保存 shell 正文、原始 argv、环境或输出。
路径/程序名本身也可能敏感。无遥测、联网、history 扫描、shell hook 或后台代理。

采用公共 XDG/HOME 状态目录，目录 0700、文件 0600，版本化原子 JSON、带密钥校验、
符号链接拒绝与 OS 锁。执行租约与短时状态写锁分开；并发或乱序完成不覆盖更新的基线。
相关调用时清理超过 30 天的可识别非活动执行记录/假设，卸载保留状态。
快照预算、密钥丢失和文件系统限制见根 README。

测试：`cargo test -p stuck`，需要 Git 和 Python 3，覆盖真实前台 PTY、两流大输出、中断和输入校验。
