# encourage：P0 生成实验

[English](README.md)

本文只覆盖本目录的隔离 Rust 实验库；它不提供可安装的 CLI 或 TUI，不是根工作区成员。本轮没有修改安装器、现有工具或终端依赖政策。实验版本与当前工作区版本保持一致，测试会检查两者。

上一级 `encourage/src/`、`Cargo.toml` 和工具级 README 存在并行开发的 TUI 工作，不属于本轮创建或验证范围。本实验不依赖该 crate，下述结果不代表它的 TUI 已通过验证。

**按最新请求，主链现在有 34 个执行步骤：28 个内容处理步骤 + 6 个明确标注的可逆过渡步骤。** 这满足调整后的总步骤范围，不代表有 34 个有效语义变换。`src/pipeline.rs` 保留未修订的 12 操作基线；当前链在 `src/expanded.rs`，词语增删规则在 `src/revision.rs`。嵌套 helper、`inspect` 和观测事件仍不计数。

## 复现

从仓库根目录运行（`--offline` 要求依赖已在本地缓存）：

```sh
cargo test --locked --offline --manifest-path encourage/experiments/Cargo.toml
cargo test --locked --offline --release --manifest-path encourage/experiments/Cargo.toml
cargo clippy --locked --offline --manifest-path encourage/experiments/Cargo.toml --all-targets -- -D warnings
cargo fmt --manifest-path encourage/experiments/Cargo.toml -- --check
cargo run --locked --offline --quiet --manifest-path encourage/experiments/Cargo.toml --example survey
```

最后一个命令是开发实验报告，不是正式 CLI，不接受业务参数。本实验只需 std 与已获准的 `blake3`，没有新增 Ratatui、信号或解析器依赖。根 `cargo test --workspace` 不会自动运行这个隔离实验。

[原始可复现数据](observations.md) 使用英文表头，包含中英文所有组合、种子向量、计数和真实执行事件。重新生成：

```sh
cargo run --locked --offline --quiet --manifest-path encourage/experiments/Cargo.toml --example survey > encourage/experiments/observations.md
```

## 第三轮：可逆过渡，再实际增删

用户明确允许过渡空操作后，新增以下步骤；这是对先前“每一步都必须改变语义”的约定调整，不把空操作伪装为内容处理。

| 步骤 | 类型 | 行为 |
| --- | --- | --- |
| 19–20 | 过渡 | `zip(0_u64..)` 配对展示序号，再 `map` 丢弃序号、复原片段 |
| 21–22 | 过渡 | `map(std::iter::once)` 单元素包装，再 `flatten` 复原；不会吞掉 `Err` |
| 23–24 | 过渡 | 固定 seed 的局部 Fisher–Yates shuffle，再按原位置排序复原 |
| 25 | 内容 | 将复原片段展开为原子 |
| 26 | 内容 | 在锚定原词前插入真正的新词，暂时保留原词 |
| 27 | 内容 | 删除原词，只删原来源，不删除新插入词 |
| 28–34 | 内容 | 句末边界、位置/预算、语言格式化与 `fold` |

Shuffle 为每个有界片段单独建立 `SplitMix64(seed=2)`，使用无偏有界取样。它不读取系统熵源、不借用生成 RNG；空片段和单原子片段保持不变。原位置标签与来源一起保留，复原不能依赖文本相等，句末 `End` 也必须在 `take_while` 前回到原位。两个原子的固定例子是 `[enjoy, a] → [a, enjoy] → [enjoy, a]`。

`Generation.draws` 只统计主题、结构和词槽选择的耗数，**不包括独立 shuffle RNG**；它不是整个程序随机调用总次数。暂停、预览限额或未来绘图不能改变两条流的生成规则。

实际增删按“语言 + 结构 + 固定词槽/后缀位置”定位，不作全文字符串替换，不依赖输入情绪，不临时抽整句。每次必须命中一个插入位置、删除一个原词；`Inserted` 来源保护新词不会被后续删除过滤误删。例如：

```text
好好吃饭，慢慢照顾自己。
→ 好好吃饭，慢慢善待自己。

Have some warm water and gently stretch your body.
→ Have some warm water, then gently stretch your body.

Give yourself credit for the small steps you take.
→ Give yourself credit for the small steps you have taken.
```

中间的插入阶段会暂时同时包含新词和待删原词，可能还不是通顺句子；这是实际观测，不应声称每一帧都有完整语法。最终仍有每语言 34 个不同结果。最终字节和词元预算在增删后检查。

## 第二轮记录：26 操作扩展

当时的扩展版没有改动词库、argv → seed 映射或随机消费顺序；本轮新增的词语修订会有意改变最终文本，不能再与旧基线比较全文相等。原来在链外的主题/结构选择现在是主链中的两个真实 `map`；其余新增操作将原本直接索引的目录、词槽候选和词级规则处理明确展开。

| 操作区间 | 数据与职责 |
| --- | --- |
| 1–2 | 随机字 → 主题和结构决定 |
| 3–8 | 双语目录 → 主题 → 结构，逐级 `flat_map` / `filter` |
| 9–14 | 结构 → 词槽 ID → 结构内候选库 → 角色筛选 → `scan` 分组 → `flatten` 完整候选组 |
| 15–16 | 完整候选组 `zip` 首个随机字；拒绝时在同一组内重试 |
| 17–19 | 固定前缀 / 随机选中规则 / 固定后缀 → 独立词原子，保留不同来源 |
| 20–26 | 句末边界、位置、语言标点、空格、首字母和最终 `fold` |

这些筛选确实改变数据流。饮食例子中：排除另一语言目录 1 个、其他主题 3 个、另一个结构 1 个；两个词槽查询结构内的真实候选库，排除错角色候选 5 个。7 个候选/分组边界事件被收集为 2 个完整候选组，不把边界或尚未收齐的部分当作词输出。

两版 `zip` 的元素类型不同：

- 12 版将每次随机尝试作为流元素，必须先丢掉拒绝项，再配对词槽。
- 26 版将一个**完整候选组**与首个随机字配对；若该字被拒绝，保留当前组，只读取更多随机字，不推进左侧词槽流，也不在 `zip` 后丢掉整个组。

已注入连续两次拒绝验证不会跳槽、错位或额外读取下一槽。固定前缀现在使用 `Fixed` 来源，只有选中候选使用 `Choice { slot, draw }`，固定后缀用 `Suffix`；不再把固定字词错误归因于某个随机决策。

目录遍历和分组比直接索引多做了实际工作，适合展示规则选择，不宣称性能优于紧凑版。仍是一个连续主链；局部有界候选物化、helper 内部迭代器及追踪均不额外计数。

## 第一轮基线的配合方式

```text
保留 argv 边界的长度前缀编码
  → 固定公开 key 的 BLAKE3 指纹
  → SplitMix64 数字流
  → 等概率主题 / 结构选择
  → 当前词槽候选数对应的拒绝采样
  → filter 拒绝项，再 zip 词槽
  → 选中词级规则并展开
  → 语言标点 / 空格 / 英文首字母
  → fold 成句
```

- 输入只决定 seed，不作情绪识别；固定 key 和 seed 不提供输入保密保证。
- 兼容性在词槽候选表中表达，不从无类型大池中任意抽词，不先选整句再拆开。
- 固定词与候选规则均由短字词构成；完整句子只存在于文档、报告和测试预期中。
- 主题和结构先于语言分支选择，因此同 seed 的中英文结构意图一致。
- 一个真实词槽有三个候选，其余目前有两个。正常扫描里每次用 4 个随机字不是永久耗数保证，拒绝会增加耗数。
- 各层选择均匀，不追求最终句子全局等概率。六种组合的结构不因组合更多就比四种组合的结构更常被选中。

## 句子实验

每种语言 4 个主题、8 个结构：`body.meal` 有 6 种组合，其余各 4 种，合计 **34 句/语言、68 句总计**。所有组合经穷举测试并列在报告中。自然度经过本轮初步文案审读，仍需发布前编辑确认，测试不能证明自然语言质量。

根据组合结果调整的草案：

- 饮食结构加入第三候选“安心” / `hearty`，让三候选验证不只存在于测试 fixture。
- `今天完成一点` 缺少明确宾语，改为 `今天有一点{进展|收获}`。
- `先走出眼前的这一步` 偏绕，省略“眼前的”。
- 英文 `a gentle break` 改为更常见的 `a short break`。
- `pace` / `rhythm` 不再自由接在固定的 `at` 后面；分别展开词级规则 `at + your + own + pace` 与 `to + your + own + rhythm`，而不是存完整分句。

```text
安心吃饭，用心善待自己。
今天有一点进展，就送给自己一点鼓励。
Enjoy a hearty meal and take a short pause.
Let yourself take a breath; you do not have to rush.
```

无类型对照：合并各结构两个可变槽位的候选，再任意配对。每语言 137 个配对中，仅 34 个符合声明的槽位约束；按槽位选择直接得到 34 个兼容结果。**这是约束满足率，不是“其余 103 句都不通顺”的语法判定。**

## RNG 与迭代器证据

当前 40 个测试包括原有基线、扩展链、三组过渡和词语修订验证：

- 长度前缀 UTF-8、参数边界、空参数、不作 Unicode 规范化，以及 6 个 argv → seed 固定向量。
- SplitMix64 参考向量；独立 `u128` 运算对照 wrapping 行为。
- 8 位模型穷举候选数 1–255；`n=3` 直接取模计数 `[86,85,85]`，拒绝偏差区间后 `[85,85,85]`。
- 对真实词库注入 `[0,0,0,3,1]`：两个头部选择后，三候选词槽拒绝 `0`、接受 `3`，再处理下一槽；不丢槽、不错位。
- seed `0..10000` 的 20,000 次双语生成中，新句子与独立的命令式修订参考实现逐项一致；结构和生成耗数仍与未编辑的 12 操作基线相同，全文则应不同。两语言全部 34 个结果都被覆盖。
- 对全部 68 个组合验证实际插入、删除一个原词、保护新词来源和新句子的空格/标点；检查增删后的字节和词元预算。
- 固定 seed 的已知 shuffle 排列、所有片段精确复原、句末标记恢复、空片段及错误保留；zip/单元素包装前后的快照相同。
- 34 个源码标记分为 28 个内容步骤和 6 个过渡步骤；真实候选筛选、分组与原子来源仍有回归测试。
- `take_while` 消费停止项但不消费尾部；`zip` 可能额外拉取一个无法配对的左项。
- 在基线的“随机尝试流”中，把拒绝过滤移到 `zip` 后会破坏槽位对齐；扩展版则按完整组配对并在组内重试，两种正确方式都与错误写法作对照。
- 实际执行按元素交错，第一次 `fold` 发生时第二个词槽尚未取数；阶段回放不是逐行执行。
- `fold(Result<...>)` 保留错误却继续拉取，`try_fold` 才短路。本实验保留已确认的 `fold`，确保输入有界，并窄范围注明 Clippy 例外；不冒称失败自动短路。
- 追踪开关和预览限额不改变结果或耗数；随机字、词元、字节预算不足返回错误，不选备用整句。

10,000 个 seed 的结构计数为 `[1206,1209,1254,1263,1264,1316,1241,1247]`，两语言一致。单句出现次数 186–360，是分层选择且组合数不同的诊断结果，不是以频率阈值判定正确性的测试。

## 边界与下一步

在 **macOS arm64、rustc 1.99.1** 上，debug/release 各 40 个测试、Clippy、格式检查及报告逐字复现检查通过。尚未执行 Linux/WSL 或最低 Rust 版本验证。

本实验未实现或验证：无参数系统熵源、生产 CLI/locale 接线、TUI、终端恢复、安装集成、正式生成协议冻结。实验消费顺序与词库不能冒充已发布的 `encourage-gen-v1`。

在允许明确标注的过渡步骤这一新约定下，主链总数 34 已进入 32–36 范围，但内容处理数是 28，不能声称满足旧的“32 个有效语义操作”要求。独立修订参考实现验证新文本，旧 12 操作基线继续验证未编辑结果及选择 RNG。词句自然度仍需发布前编辑确认；未接入并行 TUI、未冻结生成协议，也不把阶段事件数或不同原型的操作数相加。
