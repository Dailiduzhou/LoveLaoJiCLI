# afk

不带惩罚的休息；有合适前台终端时，显示一小片 Ratatui 草地。

```sh
afk 5m
afk 30s
afk 1h
```

时长仍为 ASCII 十进制正整数加小写 `s/m/h`，最多 24 小时。允许前导零；
符号、小数、空格、无单位、零和溢出返回 2。不增加业务选项或子命令。
正常结束退出场景后打印“休息结束。”；I/O 错误为 1。
Ctrl+C 取消不打印完成行，shell 通常呈现退出码 130。

## 场景与降级

- 单色 ASCII 草地仅按 `Instant` 已用时长经过四个生长阶段，带小太阳动画、
  剩余时间与按键提示。空间足够时，顶部为原始大小的 figlet 风格 `remaining`
  横幅，下方是同款大字时钟；时钟每个字符占固定等宽槽位，数字变化时冒号与
  相邻数字的位置不移动，窄字形（`1`、`:`）在槽内居中；字形横竖同倍放大，
  斜线笔画保持 45° 不断裂。
  按当前语言每八秒轮换一句安慰或激励的话。
  最多每秒 10 帧，逻辑视口上限 240×100。
- 普通输入触发“小草注意到了。”（英文 `the grass noticed.`），保留两秒；
  不重置、不延时、不扣分。q、Escape、方向键不作为退出键。
  只读本终端，不做全系统键盘/idle 监控。每帧最多读 256 字节，按键/粘贴洪泛不饿死计时器。
- Ctrl+C 取消；Ctrl+Z **先恢复终端再挂起**。进程挂起期间仍计时；fg 可恢复场景，
  bg 不读按键、不绘图。挂起期间已经到时，继续运行后立即结束。
- 启动场景须满足 stdin/stdout/stderr 为同一前台终端、TERM 非空且不是 dumb、
  至少 24×10 字符。否则安静等待，不捕捉键盘、不改模式，结束只输出一行。
  重定向 stdout 会禁用 TUI，保证脚本输出干净。运行中缩小窗口显示紧凑文本，
  极大尺寸按视口上限裁剪。始终单色以尊重 NO_COLOR；TUI 的光标/屏幕 ANSI 控制仍存在。

不保存状态、不联网、不运行外部辅助程序，不加桌面提醒、锁屏、后台常驻、
streak、评分、`--until` 或番茄钟循环。

## 为什么采用 Ratatui，以及代价

只做这一段动画，单用 Crossterm 更轻、更够用。采用 Ratatui 的收益在于缓冲差分绘制、
布局/裁剪和 TestBackend 场景测试，便于后续调整场景；它**不负责可靠恢复终端**。
本实现接受依赖代价，但所有 TUI 与生命周期代码留在 afk/，不建设共享 TUI 框架。

- Ratatui 0.30.2 关闭默认 features，仅选 crossterm_0_29。其声明的最低 Rust 为 1.88，
  workspace 仍声明 1.89。已核查依赖元数据，但本轮没有实际用 Rust 1.89 执行测试。
- Crossterm 通过 Ratatui 重导出作为绘制后端；其事件依赖仍会间接编译，但本代码不调用
  事件读取或全局 raw mode API。没有 async runtime、事件线程或鼠标捕捉。
- 既有 rustix 保存/恢复 termios；signal-hook 只提供信号原子标记；少量 libc 调用在
  UI 线程临时屏蔽 Unix 作业控制 I/O 信号，避免恢复到一半被后台读写信号挂起。
- 首次解析新增 67 个 lockfile 条目（含可选和目标平台依赖，不全在 Linux 编译）。
  当前本地 release 二进制从约 1.06 MiB 增至约 1.45 MiB；不是其他环境的大小保证。

## 终端生命周期

src/tui.rs 持有独立 /dev/tty 描述符、精确的原始 termios 快照及 RAII guard。
使用保留 ISIG 的非规范、无回显输入模式，**不用 Crossterm raw mode**。
场景运行时将流控键视为普通输入；独立打开的非阻塞读写描述符不会更改 shell
继承文件的 flags。仍在前台时，返回/挂起前丢弃场景期间排队的按键/粘贴，不回放给 shell。

界面持有终端期间，信号处理器只改原子标记；事件循环收到 SIGINT/SIGTERM/SIGHUP/SIGQUIT 后先恢复
termios、显示光标、退出备用屏幕，再按默认行为重新触发信号。SIGTSTP 先恢复再停止；
继续时重新检查前台归属，重新进入场景时再次保存当时终端设置。
错误与普通 panic 展开也运行 guard；一个恢复步骤失败仍尝试后续步骤。
非阻塞写入使终端输出反压触发失败恢复，而不是卡在 cbreak 模式里。

评估中发现：Ratatui 0.30 的 Terminal::clear() 查询光标位置，Crossterm 为等待响应
会临时启用 raw mode。这里避开该 API，使用后端直接清屏和固定视口；窗口变化时重建
有上限的终端缓冲，不走可能调用 tput 的尺寸回退。因而不吞光标响应输入、不运行外部辅助程序。

**限制**：SIGKILL、外部直接 SIGSTOP、进程 abort、硬件故障或不展开的崩溃无法运行清理。
仅上述列出的信号有托管恢复。终端断连/不可写时可能拒绝属性恢复或屏幕/光标转义序列，
此时只能尽力清理，不能承诺修复已不存在的终端。意外前台归属变化按帧检测，
不是对其他程序的原子终端租约。

## 语言、钩子与测试

支持 --help、--version、--verison。按首个非空 LC_ALL → LC_MESSAGES → LANG
选择中英文，不询问秘密或回答。

隐藏环境变量测试钩子（不进入帮助）：

- AFK_FAST=1：等待缩至已校验时长的 1%；其他值忽略。
- AFK_TEST_FAILURE=enter|draw|panic：进入终端后失败、注入后端写错误、首帧后 panic。
  仅 TUI 模式有效，未知值忽略；用于隔离测试，不供正常使用。

cargo test -p afk 包含 TestBackend 场景测试与 Python 真实前台 PTY：完成、按键洪泛、
不延时/不泄漏排队输入、缩放、中文、Ctrl+C/SIGINT/SIGTERM/SIGHUP/SIGQUIT、
初始化/写入/panic 失败、Ctrl+Z/fg/bg、挂起超过期限、dumb/小终端/重定向降级，
并逐项比较完整 termios 恢复。测试还拒绝意外的光标位置查询。

本轮只在 Linux 验证。macOS/WSL、真实终端模拟器目视检查和全部 I/O 故障时序仍待补；
不承诺原生 Windows。
